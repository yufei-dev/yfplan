# 计划文件格式规范（yfplan JSON）

> **本文定义「计划文件」的标准格式**（`formatVersion: 1`）。
> 页面内置计划就是一份这样的 JSON（见 `index.html` 中
> `<script type="application/json" id="planData">`）。
> 任何人按本格式手写的计划文件，都可以通过「存档 → 导入文件」加载。

---

## 一、如何导入

1. 把计划存成 `.json` 文件（UTF-8）
2. 打开网站 → 右侧「存档」面板 → 点 **导入文件（进度/计划）**
3. 页面自动识别：含 `"format": "yfplan"` 的按**计划文件**处理（保存并刷新）；
   含 `"items"` 的按**打卡进度文件**处理（合并恢复）
4. 导入的计划会保存在浏览器本地，可通过 **「↺ 恢复默认计划」** 还原

打卡记录格式与本文件格式**互不影响**：打卡数据仍是 `{updated, items}`
（键如 `d-2026-10-14-m`、`w1-m0`），文件存档名 `AAA打卡存档.json` 保持不变。

---

## 二、顶层字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `format` | string | ✅ | 固定为 `"yfplan"`（识别标志） |
| `formatVersion` | number | ✅ | 格式版本，目前为 `1` |
| `name` | string | | 计划名称（展示用） |
| `exams` | object | | `{"math":"YYYY-MM-DD","english":"YYYY-MM-DD"}`，用于倒计时 |
| `listeningSets` | string[] | | 听力材料清单（按序轮换 Section B → C） |
| `templates` | object | ✅ | 每日任务模板：`phase1`（前期）/ `phase3`（后期） |
| `weeks` | array | ✅ | 周计划列表（**周数=数组长度**，页面自动适配） |
| `timeline` | array | | 左侧备考时间线（色块分区） |

## 三、`templates` 结构

`templates.phase1` 与 `templates.phase3` 内部均为「时段槽位」对象：

| 槽位键 | 使用阶段 | 字段 |
|---|---|---|
| `morning` | 两阶段 | `t`（任务文案）、`dur`（时长）、`tool`（方法，字符串数组，可多行） |
| `noon` | 两阶段 | 同上（阶段一为听力精听；阶段三为精听+泛听） |
| `read` | 阶段一 | 同上（阅读日的中午任务） |
| `nb` / `ft` | 阶段一 | 同上（碎片时段：不背例句 / 泛听，按日交替） |
| `frag` | 阶段三 | 同上（碎片时段：僻义清单） |
| `sleep` | 两阶段 | 同上（睡前复盘） |

> 阶段一（phase1）的听力与阅读按日交替、碎片随之交替，由代码自动排布。

## 四、`weeks` 数组元素

| 字段 | 类型 | 说明 |
|---|---|---|
| `mon` | string | 该周周一日期 `YYYY-MM-DD`（全计划的坐标基准） |
| `from` | number | 起始日索引 0–6（周一=0）。整周可省（默认 0） |
| `to` | number | 结束日索引 0–6。整周可省（默认 6） |
| `phase` | string | `"phase1"` 或 `"phase3"`，决定用哪套模板 |
| `title` | string | 周主题（如「诊断周」） |
| `math` / `eng` | string[] | 当周数学/英语任务（可空数组） |
| `miles` | string[] | 当周打卡项（即右侧「本周任务」勾选项） |
| `eve` | array(7) | 每天晚间任务，**周一→周日**，共 7 项；空白天写 `null` |

`eve` 元素写法：`{"t":"任务文案","k":"类型"}`，可选 `"tool":["自定义方法…"]` 覆盖默认。

`k` 类型表（缺省方法文案由代码内置，见 `TOOLK`）：

| k | 含义 |
|---|---|
| `m` | 数学专题 |
| `limit` | 中档限时训练 |
| `sim` | 全真模拟 |
| `exam` | 考试日 |
| `rest` | 休整 |
| `diag` | 诊断 |
| `wrap` / `refresh` | 错题复盘 / 滚动 |
| `e` / `e-sim` | 英语轮换 / 拆分模考 |
| `warm` / `write` | 保温跟读 / 写译专项 |

## 五、`timeline` 结构

分区块：`{"color":"blue|amber|green|red|outline","title":"…","items":[…]}`；
条目：`{"d":"起始日","e":"结束日(可选)","t":"标题","w":跳转周序号,"extra":true(可选),"lab":"日期显示覆盖(可选)"}`。

## 七、设计约束（改格式前必读）

1. **向后兼容**：新增字段一律可选；`formatVersion` 变化必须写进 CHANGELOG。
2. **打卡数据独立**：计划可更换，打卡键（`w3-m0` 等）含义随"第 3 周的里程碑 0"，
   更换计划后旧打卡可能对应新内容——这是已知取舍，v1.5.0 多用户化时再细化。
3. **渲染零改动原则**：页面代码只依赖`归一化后`的内部结构（`normalizePlanData()`），
   格式演进时优先改加载器，不动渲染代码。
