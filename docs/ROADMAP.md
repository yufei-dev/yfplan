## v1.2.0 — 数据外部化

**为什么先做这个**：现在九周计划、任务模板全部**硬编码在 `index.html` 里**。
不把它们抽出来，用户就无法导入自己的计划——这是所有多用户功能的前置条件。

- [ ] 把 `TMPL`、`WEEKS`、时间线、倒计时目标等抽成独立数据文件
      或页面内的一个 `<script type="application/json" id="planData">` 块
- [ ] 定义**计划文件格式**（JSON Schema），写好注释和版本字段
- [ ] 「从文件恢复」功能升级：支持导入别人的计划文件
- [ ] 保留现有 `{updated, items}` 打卡记录格式不变（向后兼容）

**验收**：用一个手写的 JSON 替换计划数据，页面正常渲染出不同的课程表。

## v1.3.0 — 接入用户认证

- [ ] 注册 [Supabase](https://supabase.com) 免费项目（选**东京**或**新加坡**节点）
- [ ] 建 `profiles` 表 + 注册触发器（新用户自动建 profile 行）
- [ ] 页面加登录/注册界面（邮箱 + 密码）
- [ ] 未登录时：保持现有行为（纯本地），不打扰老用户
- [ ] 已登录时：顶部显示邮箱 + 退出按钮
- [ ] 「存档」面板改为**登录后才显示**（本阶段仅前端隐藏，真正的安全在 v1.5.0）

**验收**：能注册、能登录、刷新后登录状态保持、能退出。

**风险**：免费版内置邮件服务有发信频率上限，注册量大时可能收不到确认邮件。
届时可关闭「邮箱确认」或配置自己的 SMTP。

## v1.5.0 — 管理员角色与权限隔离

## 待定 / 需要你决定的问题

1. **用户规模**：只给几个同学用，还是可能上百人？
   - 几十人：Supabase 免费版绰绰有余
   - 上百人且要求快：可能需要考虑付费或国内云
2. **是否允许用户注册**：开放注册，还是只给邀请码？
3. **计划数据是否共享**：用户能不能看到别人的计划？还是完全私有？

这几个问题不急着现在回答，做到 v1.3.0 之前给我答复就行。
