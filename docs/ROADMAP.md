## v1.3.0 — 数据外部化

**为什么必须做**：现在九周计划、任务模板仍以 JS 字面量形式写在 `index.html` 里。
不把它们变成「可替换的数据」，用户就无法导入自己的计划——这是所有多用户功能的前置条件。

- [ ] 把 `TMPL`（任务模板）、`WEEKS`（周计划）、`TL`（时间线）整理成一份结构化的
      **计划数据对象**（可放在页面内的 `<script type="application/json">` 块中）
- [ ] 定义 **计划文件格式**（JSON Schema），带版本字段，写清每个字段含义
- [ ] 「从文件恢复」功能升级：能导入他人的计划文件
- [ ] **保持向后兼容**：现有打卡记录 `{updated, items}` 格式不变

**验收**：手写一份只有 4 周的计划 JSON，替换后页面正常渲染出 4 周课表，
且 `TOTAL_WEEKS` 自动变成 4。

**注意**：`SAVE_FILE` 的文件名不能跟着改，见 CHANGELOG v1.2.0 的说明。

## 待定 / 需要决定的问题

1. **用户规模**：只给几个同学用，还是可能上百人？
   - 几十人：Supabase 免费版绰绰有余
   - 上百人且要求快：可能需要考虑付费或国内云
2. **是否允许用户注册**：开放注册，还是只给邀请码？
3. **计划数据是否共享**：用户能不能看到别人的计划？还是完全私有？
4. **是否启用自定义域名**：站点已随仓库改名为 `/yfplan/`，
   未来若再改名 URL 还会变。绑定自定义域名可让网址永久稳定
   （若你已拥有 `ccwu.cc`，可免费加一个子域名，GitHub Pages 支持）。
